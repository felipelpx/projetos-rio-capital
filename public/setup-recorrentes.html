↻ Setup — Despesas Recorrentes

As avenças, seguros e contratos que se repetem passam a ser lançados uma vez só. Para isso é preciso criar a tabela despesas_recorrentes, onde fica guardada a regra — o Fluxo Futuro gera as ocorrências a partir dela. Corre o SQL abaixo uma única vez.

1Abre o SQL Editor do Supabase

Vai a Supabase SQL Editor e cola o SQL abaixo.

2Corre o SQL

create table if not exists despesas_recorrentes (
  id            text primary key,
  empresa       text        not null,
  tipo          text        not null default 'saida',   -- 'saida' ou 'entrada'
  descricao     text        not null,
  categoria     text,
  subcategoria  text,
  valor         numeric     not null,                   -- valor BASE, sem IVA
  taxa_iva      numeric     not null default 23,        -- 23 | 13 | 6 | 0
  data_inicio   date        not null,                   -- primeira ocorrência
  data_fim      date,                                   -- data limite; nulo = sem fim
  periodicidade text        not null default 'mensal',  -- mensal|bimestral|trimestral|semestral|anual
  ativa         boolean     not null default true,
  obs           text,
  criado_por    uuid,
  created_at    timestamptz not null default now(),
  updated_at    timestamptz not null default now()
);

create index if not exists idx_recorrentes_empresa on despesas_recorrentes(empresa);
create index if not exists idx_recorrentes_ativa   on despesas_recorrentes(ativa);

alter table despesas_recorrentes enable row level security;

drop policy if exists "ler recorrentes"    on despesas_recorrentes;
drop policy if exists "criar recorrentes"  on despesas_recorrentes;
drop policy if exists "editar recorrentes" on despesas_recorrentes;
drop policy if exists "apagar recorrentes" on despesas_recorrentes;

create policy "ler recorrentes"    on despesas_recorrentes for select using (true);
create policy "criar recorrentes"  on despesas_recorrentes for insert with check (true);
create policy "editar recorrentes" on despesas_recorrentes for update using (true) with check (true);
create policy "apagar recorrentes" on despesas_recorrentes for delete using (true);

-- Atualizações em tempo real (para a despesa aparecer sem recarregar)
do $$ begin
  if not exists (select 1 from pg_publication_tables
                 where pubname = 'supabase_realtime' and tablename = 'despesas_recorrentes') then
    alter publication supabase_realtime add table despesas_recorrentes;
  end if;
end $$;

notify pgrst, 'reload schema';

3Confirma

Abre o ERP → Fluxo Futuro → escolhe um projeto no filtro do topo. Aparece o botão ↻ Despesas recorrentes.

Com o filtro em "Todos os Projetos" o botão fica apagado: uma despesa recorrente é sempre de uma empresa.

Nota sobre o valor: guarda-se o valor sem IVA e a taxa à parte. O Fluxo Futuro conta o valor com IVA, que é o que sai do banco. Assim o custo do projeto e o caixa ficam ambos certos, sem haver dois campos a dizer o mesmo.
